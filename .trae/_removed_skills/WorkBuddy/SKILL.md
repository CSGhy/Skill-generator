# Buddy 加油站每日自动签到

## 一、自动化任务配置

在 WorkBuddy 新建自动化时按此填写：

| 配置项 | 值 |
| --- | --- |
| 名称 | Buddy加油站每日自动签到 |
| 模型 | HY3 |
| 执行频率 | 每天（recurring） |
| 触发时间 | 09:00 |
| 调度规则（RRULE） | `FREQ=DAILY;BYHOUR=9;BYMINUTE=0` |
| 状态 | 启用（ACTIVE） |

## 二、设置指令

本 agent 一次性执行，用于初始化；之后每天由上面配置的自动化自行触发。

1. 先按下方「任务提示词正文 · 前置」完成 Skill 的安装与审计（若已装且为 v1.0.3 则跳过）。
2. 依据上方「自动化任务配置」调用 WorkBuddy 自带自动化功能创建该每日任务：
   - 名称、模型（HY3）、执行频率（每天）、触发时间（09:00）、调度规则（`FREQ=DAILY;BYHOUR=9;BYMINUTE=0`）、状态（ACTIVE）严格按上表填写；
   - 把下方「任务提示词正文」整段（不含前置）作为该自动化的提示词写入；
   - 若同名自动化已存在则跳过创建，不要重复建。
3. 创建后不要手工触发，等待 09:00 真实自行运行；每日任务只做签到，绝不再创建 / 重复创建自动化。

## 三、任务提示词正文

**目标**：每天自动领取 Buddy 加油站签到积分，且绝不泄露或改动登录凭据。

### ★ 前置（由本 agent 在首次运行时执行一次）

> 仅当 workbuddy-checkin Skill 未安装时才做，已安装则直接跳过，**绝不每次触发都重复执行或重新下载未知代码**。

- 若 Skill 已存在于 `~/.workbuddy/skills/workbuddy-checkin/` 且版本为 `v1.0.3`，跳过本步，直接进入每日签到。
- 若未安装，则按顺序：
  1. 从该官方仓库 `github.com/cat-xierluo/legal-skills` → `skills/workbuddy-checkin` 下载真实源码（版本锁定 v1.0.3），逐文件审阅（不要只看 README）；
  2. 执行 9 项安全检查——
     - 仅读取本机登录态且不写；
     - refreshToken 不读不传；
     - accessToken 只发往官方 `copilot.tencent.com`，不上传任何第三方；
     - 实际请求域名仅为官方域名；
     - token 不落盘、不回显；
     - 不修改 WorkBuddy 本体；
     - 不修改本机登录态文件；
     - 不自动安装 Electron；
     - 不创建后台常驻程序或系统级定时任务。
  3. 全部通过才安装并锁定版本，任何一项不通过则中止并报告，**绝不安装**。
- 本机走新版 Node 主路径时纯 Node 即可读登录态，无需安装 Electron。
- 无论前置还是每日运行，都禁止打印 token、禁止修改登录态、禁止自动安装多余依赖。

### ★ 每日签到行为

1. 调用 workbuddy-checkin Skill 执行当天签到检查。
2. 若今日未签到则领取；若已经签到则安全退出，**绝不重复领取**。
3. 以响应体中的 `code` 字段为准：
   - `code=0` 表示领取成功（记录本次积分与连续签到天数）；
   - `code=10001` 视为「今日已签到」，直接安全退出。
4. 注意：网关可能用 HTTP 400 包装业务码，不要因 HTTP 状态码为 400 就误判为失败，**必须以响应体里的 `code` 字段判断**。
5. 不要用 `checkin-status` 的 `today_checked_in` 字段判断状态（该字段不可靠），以 `daily-checkin` 实际返回的 `code` 为准。
6. 异常处理：仅记录真实失败原因，不无限重试（网络错误最多重试 1 次）；不要把失败写成成功。

### ★ 绝对禁止（任何情况下）

- 禁止在任何输出 / 日志 / 终端中打印 token、accessToken、refreshToken 或任何凭据；
- 禁止修改本机登录态文件；
- 禁止自动安装 Electron 或其他非必要依赖。

### ★ 完成后只汇报一句话（根据状态选择）

- 「成功领取」（并简述本次积分与连续天数）；
- 「失败原因：&lt;真实原因，且不含任何 token 或凭据&gt;」。
