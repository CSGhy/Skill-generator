# 基于文档的测试用例生成器

这个skill从PRD、需求说明、接口文档中快速产出结构化、可落地的测试用例。它支持多种输入格式，按照固定「测试设计策略 + 专用标准」生成测试用例，并可以对接公司现有的Word/Excel模板。

## 📋 快速参考卡片

### 基本指令格式

```
/doc-based-testcase-generator [文档内容] [选项]
```

#### 参数说明

**必填参数**：
- `document`：文档内容或文档路径（必填）

**可选参数**：
- `--doc-type`：文档类型，可选值：`prd`|`requirement`|`api`|`user-story`|`code`（默认：自动识别）
- `--test-type`：测试类型，可选值：`functional`|`boundary`|`negative`|`integration`|`performance`|`security`|`all`（默认：`all`）
- `--standard`：测试标准，可选值：`standard`|`api`|`automation`|`custom`（默认：`standard`）
- `--format`：输出格式，可选值：`md`|`csv`|`excel`|`json`|`word`（默认：`md`）
- `--template`：自定义模板文件路径（默认：内置模板）
- `--output`：输出文件路径（默认：`docs/`目录）
- `--risk-based`：基于风险的测试（默认：`true`）
- `--coverage`：测试覆盖率，可选值：`100`|`80`|`60`|`40`（默认：`100`）

### 文档类型识别

| 文档类型 | 识别特征 | 测试重点 |
|---------|---------|---------|
| PRD | 包含"需求"、"功能"、"用户故事"等关键词 | 功能流程、业务规则 |
| 需求说明 | 包含"需求"、"规格"、"说明"等关键词 | 需求覆盖、边界条件 |
| 接口文档 | 包含"API"、"接口"、"参数"、"响应"等关键词 | 参数验证、错误码、边界值 |
| 用户故事 | 包含"作为...我想要...以便..."格式 | 用户场景、验收标准 |
| 代码 | 包含代码块、函数定义 | 逻辑覆盖、异常处理 |

### 测试标准说明

| 标准 | 适用场景 | 特点 |
|------|---------|------|
| standard | 通用功能测试 | 全面覆盖，包含功能、边界、负向 |
| api | 接口测试 | 关注参数、错误码、响应格式 |
| automation | 自动化测试 | 可执行、可维护、可复用 |
| custom | 自定义标准 | 根据references目录下的规范 |

## 智能提问与异常处理

### 智能提问策略

#### 提问时机

1. **文档信息不完整时**
   - 缺少功能描述
   - 缺少业务规则
   - 缺少约束条件

2. **测试标准不明确时**
   - 用户未指定测试标准
   - 用户未指定输出格式
   - 用户未指定测试覆盖率

3. **测试用例需要补充时**
   - 缺少边界测试
   - 缺少负向测试
   - 缺少集成测试

#### 提问原则

1. **精准性**：问题要具体明确
2. **必要性**：只问必要的问题
3. **简洁性**：问题要简洁易懂
4. **引导性**：问题要引导用户思考

#### 提问示例

**场景1：文档信息不完整**

**智能体**：文档中缺少以下关键信息：
1. 用户注册的密码规则是什么？
2. 商品浏览是否有分页限制？
3. 购物车是否有商品数量限制？

请补充这些信息，以便生成更准确的测试用例。

**场景2：测试标准不明确**

**智能体**：请选择测试标准：
1. 标准测试规范（推荐）
2. API测试规范
3. 自动化测试规范
4. 自定义规范

**场景3：测试用例需要补充**

**智能体**：根据文档分析，建议补充以下测试场景：
1. 边界测试：密码长度边界值测试
2. 负向测试：重复用户名注册测试
3. 集成测试：注册后自动登录测试

是否需要补充这些测试场景？

   - 提供测试标准示例

4. **模板文件不存在**
   - 提示检查模板文件路径

## 测试数据管理

### 测试数据类型

1. **正常数据**
   - 有效输入
   - 合法数据
   - 符合规则的数据

2. **边界数据**
   - 最小值
   - 最大值
   - 临界值

3. **异常数据**
   - 无效输入
   - 非法数据
   - 不符合规则的数据

4. **特殊数据**
   - 空值
   - NULL值
   - 特殊字符

### 测试数据管理策略

1. **数据独立性**
   - 每个测试用例使用独立数据
   - 避免数据污染
   - 支持并行执行

2. **数据可复用**
   - 测试数据参数化
   - 数据驱动测试
   - 数据模板化

3. **数据安全性**
   - 敏感数据脱敏
   - 数据加密存储
   - 访问权限控制

## 常见问题（FAQ）

### Q1：如何选择测试标准？

**A**：根据文档类型选择测试标准：
- PRD → 标准测试规范
- 接口文档 → API测试规范
- 自动化需求 → 自动化测试规范
- 自定义需求 → 自定义规范

### Q2：如何自定义测试模板？

**A**：在assets目录下创建自定义模板文件，使用占位符：
- `{case_id}`：用例ID
- `{module}`：模块
- `{scenario}`：测试场景
- `{steps}`：测试步骤
- `{expected}`：预期结果
- `{priority}`：优先级
- `{risk}`：风险等级
- `{type}`：测试类型

### Q3：如何对接公司模板？

**A**：将公司模板放到assets目录下，使用--template参数指定：
```bash
--template assets/company_template.xlsx
```

### Q4：如何提高测试覆盖率？

**A**：采用以下策略：
1. 增加测试用例数量
2. 增加测试类型
3. 增加测试场景
4. 使用测试设计方法

### Q5：如何减少测试用例数量？

**A**：采用以下策略：
1. 合并相似测试用例
2. 删除冗余测试用例
3. 优化测试数据
4. 使用参数化测试
