# 多代理研究级证明器

> 源自 Crouzeix 猜想项目的工程实践：13 个线程、9,173 条形式化推理摘要、14 小时 50 分钟墙上时间、194 万 token、1,379 次数值实验命令调用 → 一份可编译的 7 页 LaTeX 证明，通过三次独立端到端审计。

## 何时使用

当任务同时满足下列全部条件时调用：

- **研究级复杂度**：不是一次性查询或简单修复；需要真正的数学/算法/架构推理。
- **假定存在肯定解**：必须迭代直到找到完整解，而非报告"问题困难"。
- **要求具体交付物**：输出必须是可编译的工件（LaTeX、Lean、源代码、形式化规格）——不是散文式回答。
- **可接受多轮对抗式开发**：以小时计的迭代工作，而非秒级。
- **用户明确邀请结构化多代理方案**，或任务规模使单代理处理明显不足。

不要用于：
- 琐碎修复、查询、单行编辑。
- 已知存在标准流程的任务。
- 对话式或探索性问题（"我们该如何处理 X？"）。
- 用户只要一个建议、不要完整交付物的任务。

## 核心哲学（不可协商）

1. **多样化组合优先。** 启动时即配备 ≥6 条**实质**不同的路线（不同 formulations、invariants、reductions、代数观点、结构归纳、分解、流公式、转移系统、嵌入、极值论证、计算合理性检验）。不允许用措辞差异冒充多样性。

2. **保护早期独立性。** 不要告诉大多数代理当前倾向的方法。在交叉授粉之前，让它们独立发展。若所有代理都收敛到同一条"诱人但不完整"的归约，即视为独立性测试失败。

3. **维护显式方法家族注册表。** 按代理使用的数学/算法**思想**分组，而非按措辞。若多代理收敛到同一家族，把部分重定向到探索不充分的形式。

4. **拒绝优雅垄断。** 一条路线若最终落到与原问题等价强度的引理上，**不算接近完成**，除非它给出该引理的真正新证明。拒绝"优雅即进度"。

5. **诚实标记阻塞。** 当一条路线在"定理强度缺失引理"处停滞时，标记为 `blocked`。只有当某人提出实质上**新的机制、不变量或构造**时才可重开。

6. **对抗审计贯穿全程。** 每个候选证明都必须检查：缺口（gaps）、条件性（conditionals）、含糊其辞（handwavings）、对等价陈述的循环引用。对抗代理必须返回**具体引理、构造、方程或反例**。拒绝状态报告、模糊乐观、"routine"声明。

7. **仅在完整完成后返回。** 不要因当前路线失败或报告定理强度缺口而返回。启动新一轮、仅在出现真正新机制时重开阻塞路线、搜索全新 formulations。**只有当完整肯定解找到且存活对抗审计时**才返回。

## 工作流程

### 第 0 轮 —— 设置（根代理）

1. 把形式化问题陈述写成可编译工件（LaTeX / Lean / 源代码）。固定其 SHA-256。
2. 初始化**方法家族注册表**（模板见下），行为空。
3. 定义交付格式与验收标准：
   - 干净编译（无警告）
   - ≥3 次独立端到端对抗审计
   - 通过计算合理性闸门
   - 目标状态机显式置为 `complete`
4. 设定时间/token 预算上限（默认：每轮 6 小时 / 50 万 token，可扩展；研究级任务可扩展至 15 小时 / 200 万 token 总量）。

### 第 1 轮 —— 组合启动

启动 ≥6 个直接子代理，每个分配到注册表中**不同**的家族。路径命名：`/root/<family_slug>`。

数学任务的示例家族：
- `analytic_route`（Herglotz / 正实核）
- `geometric_route`（凸几何 + 支撑半平面）
- `algebraic_route`（伴随代数约束 + Gramian）
- `inductive_route`（结构归纳）
- `extremal_route`（变分 / 饱和分析）
- `computational_sanity_route`（随机数值验证）

对每个子代理，根代理的派发消息**必须**：
- 仅陈述问题与交付格式。
- **不**披露根代理当前倾向的方法。
- 要求返回**具体工件**（引理、构造、方程、反例）——而非状态报告。
- 禁止 "routine" / "it can be shown" / "standard" 之类含糊措辞。

### 第 2..N 轮 —— 综合、质疑、重定向

每轮结束后，根代理：

1. **综合**：从每个存活代理收集具体工件；更新方法家族注册表。
2. **质疑**：对每个候选片段，派发一个**对抗审计代理**（独立代理）去找 gaps、conditionals、handwavings、循环依赖。审计代理**不得**与产出该片段的代理相同。
3. **重定向**：
   - 若 ≥3 个代理收敛到同一家族，杀掉重复者，把它们重派到探索不充分的家族。
   - 若一条路线 `blocked` 且无新机制，保持阻塞。
   - 若一条路线报告"定理强度缺失引理"，标记 `blocked`，要求真正新机制才能重开。
4. **派生二级子代理**：当某个直接子代理报告了一个有前景、需要更深入探索的子机制时：`/root/<family_slug>/<sub_mechanism>`。
5. **允许且鼓励晚启动**：即使在后期轮次，也要持续启动新家族。Crouzeix 案例中最终赢家（`hardy_duality_route`）正是**最后**被启动的直接子代理。
6. **交叉授粉**仅在各独立代理已把自己的思路发展得足够暴露真实优势与缺口后进行——绝不能更早。

### 终轮 —— 完成性测试

一个候选只有当**下列全部**满足时才算完成：

- (a) 工件干净编译，无警告。
  - LaTeX：`latexmk -pdf -interaction=nonstopmode -halt-on-error <file>.tex`
  - Lean：`lake build && lake env lean <AxiomAudit>.lean`
  - 源代码：对应语言的严格构建。
- (b) 通过 ≥3 次独立端到端对抗审计，且审计代理**不是**该工件的作者。
- (c) 方法家族注册表显示获胜家族，并对每个其他家族给出一句被拒绝/阻塞的理由。
- (d) 通过计算合理性闸门（见下）。
- (e) 目标状态机显式置为 `complete`（见输出契约）。

## 方法家族注册表（模板）

根代理全程维护此表，每轮后更新。

```
| 家族 slug            | 核心思想（≤30 字）                    | 状态      | 负责代理路径                       | 阻塞引理 / 拒绝原因                                            |
|----------------------|--------------------------------------|-----------|------------------------------------|------------------------------------------------------------------|
| analytic_route       | Herglotz / 正实核采样                 | active    | /root/analytic_route               | —                                                                |
| geometric_route      | 凸几何 + 支撑半平面                   | active    | /root/geometric_route              | —                                                                |
| algebraic_route      | 伴随代数约束 + Gramian               | active    | /root/algebraic_route              | —                                                                |
| inductive_route      | 维数 n 的结构归纳                    | blocked   | /root/inductive_route              | 卡在定理强度缺失引理（尚无新机制）                              |
| extremal_route       | 变分 / 饱和分析                      | active    | /root/extremal_route               | —                                                                |
| computational_sanity | numpy 随机小规模验证                 | supporting| /root/computational_sanity         | —                                                                |
| ...                  | ...                                  | ...       | ...                                | ...                                                              |
| hardy_duality_route  | Herglotz 表示 + 预解核               | **winner**| /root/hardy_duality_route          | —                                                                |
```

状态取值：`active` | `blocked` | `supporting` | `superseded` | `winner`。

`blocked` 路线只有当某个代理提出**实质上新的机制、不变量或构造**时才可重开——仅换措辞不算。

## 对抗审计清单

对每个候选片段，对抗审计代理**必须**返回下列之一：

- 一个**具体反例**（含显式参数）。
- 一个**具体缺口**（引用失败的具体行/推理）。
- 一个**循环依赖**（该片段归约到与原问题等价的陈述）。
- 一次**无条件通过**（含逐行验证过的显式引理链）。

禁止的审计输出（视为无效，重新派发一位新审计代理）：
- "看起来是对的"
- "这是 routine 的"
- "标准论证适用"
- "大概是对的"
- 任何没有具体工件的状态报告。

## 计算合理性闸门（终轮前强制）

宣布完成前，运行一次与领域匹配的随机小规模数值检验：

- **数学不等式**：随机小规模案例（如 3×3 矩阵、4 次多项式、≥600 次试验）。界在数值上必须成立；记录最坏比值。
- **算法声明**：在文档化的输入分布上的随机输入；验证声明的复杂度/正确性不变量。
- **架构声明**：用合成负载在边界条件下压力测试。

在交付物的审计日志中记录：
- 脚本（Python / 对应语言）完整源代码。
- 墙上时间。
- 数值结果（最坏比值、错误数等）。

若合理性闸门失败，候选被拒绝——回到第 2..N 轮。

## 输出契约

最终交付物**必须**包含以下全部：

1. **工件本身**（`proof.tex` / `Theorem.lean` / `solution.py` 等）——可编译、无警告、无 `sorry` / `admit` / `TODO` / `FIXME`。
2. **审计日志**（`AUDIT.md` 或追加到 `README.md`）：
   - 每次对抗审计一行。
   - 每行注明：审计代理身份、被审片段、结论（反例 / 缺口 / 循环 / 通过）、以及具体引理链或反例。
3. **方法家族注册表快照**——最终状态表，显示赢家与被拒绝/阻塞的备选，各附一句理由。
4. **计算合理性报告**——脚本、运行时间、数值结果。
5. **目标状态**——根代理**必须**显式发出 `complete` 状态。在有目标状态 API 的代理框架中，调用等价于 `tools.update_goal({status: "complete"})` 的接口；在普通 LLM 会话中，输出字面行 `GOAL_STATE: complete` 作为最后一行。缺此，任务不算完成。

## 反模式（显式禁止）

- ❌ 固定代理分配，如"N 个代理用于策略 X"。
- ❌ 把当前倾向方法告诉大多数代理。
- ❌ 把"优雅归约"当作进度，而它落到定理强度引理。
- ❌ 无真正新机制就重开阻塞路线。
- ❌ 在代理充分发展思路前交叉授粉。
- ❌ 把部分结果、归约或"尽力而为"摘要当作最终交付。
- ❌ 因当前路线失败就返回。
- ❌ 跳过计算合理性闸门。
- ❌ 没有 ≥3 次独立审计就宣布完成。
- ❌ 用户要可编译工件却返回散文。
- ❌ 让作者代理当自己的审计代理。

## 资源与失败模式说明

- **规模预期**：研究级任务可能需要数小时与 ≥100 万 token。据此规划；不要在第 3 轮就因"花的时间太长"而中止。
- **收敛失败**：若**所有**家族连续 ≥2 轮 `blocked` 且无新机制，浮现当前最强的、已被严格证明的部分结果及其**确切**剩余缺口——但仅作为状态更新，**不**作为最终返回。继续启动新家族。
- **晚启动赢家**：Crouzeix 记录的获胜路线是最后启动的直接子代理。抵制过早修剪后期家族的冲动。
- **独立性侵蚀**：若注册表显示 ≥3 条路线尽管 slug 不同却塌缩到同一思想，强制杀掉重复者并重派到真正不同的家族。

## 执行模式

**在带有多代理 API 的环境中**（Codex App Server、自主代理框架等）：
- 用 `spawn_agent` / `send_message` / `wait_agent` 把任务树实体化。
- 代理严格按注册表路径命名。
- 把整段对话记录在单一 Markdown 文件中，`##` = 线程、`### Turn N` = 轮次、`####` = 条目类型（推理摘要 / 命令 / 审计 / 代理间消息），与 Crouzeix 源记录格式一致。

**在普通单会话 LLM 中**（无 spawn API）：
- 通过会话内角色切换模拟多代理树："以 /root/analytic_route 身份：..."。
- 仍需在回复中显式维护方法家族注册表。
- 仍需在宣布完成前进行 ≥3 次模拟对抗审计（每次置于独立角色切换块中）。
- 仍需通过计算合理性闸门。
- 仍需输出 `GOAL_STATE: complete` 作为最后一行。

## 溯源

本技能提炼自 Crouzeix 猜想项目展示的工程实践：
- 13 个线程（1 根 + 10 直接子代理 + 2 二级子代理）
- 9,173 条形式化推理摘要
- 1,379 次数值实验命令调用
- 14 小时 50 分钟墙上时间、194 万 token
- 三次独立端到端审计 → 一份可编译的 7 页 LaTeX 证明

它是对该项目方法论的泛化，**不**构成对正确性的保证。原项目在创建本技能时形式化同行评审仍在进行；本技能产出的任何结果同样适用该标准。
