# 知识库管理

这个SKILL用于管理测试用例知识库和经验积累，提供结构化的知识查询和管理功能，帮助测试人员快速获取测试知识和最佳实践。

## 📋 快速参考卡片

### 基本指令格式

```
/knowledge-base [查询内容] [选项]
```

#### 参数说明

**必填参数**：
- `query`：查询内容（必填）

**可选参数**：
- `--category`：知识分类，可选值：`testcase`|`scenario`|`best-practice`|`trap`|`standard`|`template`|`all`（默认：`all`）
- `--format`：输出格式，可选值：`md`|`json`|`csv`|`table`（默认：`csv`）
- `--include-examples`：是否包含示例，可选值：`true`|`false`（默认：`true`）

```json

## 常见陷阱库

### 测试用例设计陷阱

#### 陷阱1：遗漏边界值测试
**现象**：只测试正常值，忽略边界值

**后果**：无法发现边界相关的缺陷

**解决方案**：
- 使用边界值分析技术
- 测试最小值、最大值、最小值-1、最大值+1

#### 陷阱2：测试用例依赖性强
**现象**：测试用例之间有强依赖关系

**后果**：测试用例难以独立执行和维护

**解决方案**：
- 确保测试用例独立性
- 每个测试用例包含完整的测试步骤
- 使用测试数据准备脚本

#### 陷阱3：测试用例描述不清晰
**现象**：测试用例描述模糊，难以理解

**后果**：测试人员无法准确执行测试用例

**解决方案**：
- 使用清晰的语言描述测试步骤
- 包含具体的输入和预期输出
- 提供测试数据示例

### 测试执行陷阱

#### 陷阱1：忽略环境差异
**现象**：在测试环境测试，但在生产环境失败

**后果**：测试结果不准确

**解决方案**：
- 保持测试环境和生产环境一致
- 记录环境配置信息
- 在多个环境验证测试结果

#### 陷阱2：测试数据不真实
**现象**：使用不真实的测试数据

**后果**：无法发现真实场景的问题

**解决方案**：
- 使用真实的测试数据
- 覆盖各种数据场景
- 定期更新测试数据

#### 陷阱3：测试结果记录不完整
**现象**：测试结果记录简单，缺少关键信息

**后果**：无法复现和定位问题

**解决方案**：
- 详细记录测试步骤
- 记录实际结果和预期结果
- 截图保存
- 记录环境信息

### 测试管理陷阱

#### 陷阱1：测试覆盖率计算不准确
**现象**：测试覆盖率计算方式不统一

**后果**：测试覆盖率数据不可靠

**解决方案**：
- 统一测试覆盖率计算标准
- 使用自动化工具计算覆盖率
- 定期验证覆盖率数据

#### 陷阱2：测试优先级划分不合理
**现象**：测试优先级划分随意，缺乏依据

**后果**：测试资源分配不合理

**解决方案**：
- 基于风险划分优先级
- 考虑业务重要性
- 考虑缺陷影响

## 最佳实践库：测试用例设计

### 测试用例设计原则

#### 1. 完整性
**说明**：测试用例应该覆盖所有功能需求

**实践方法**：
- 基于需求文档设计测试用例
- 使用需求-测试用例映射表
- 定期检查测试用例覆盖率

**示例**：
| 需求 | 测试用例 | 覆盖 |
|------|---------|------|
| 用户注册 | TC001, TC002, TC003 | 完整 |
| 用户登录 | TC004, TC005, TC006 | 完整 |
| 密码找回 | TC007, TC008 | 完整 |

#### 2. 独立性
**说明**：测试用例之间应该相互独立

**实践方法**：
- 每个测试用例包含完整的测试步骤
- 避免测试用例之间的依赖
- 使用测试数据准备脚本

**示例**：
```python
# 错误示例：测试用例有依赖
def test_login():
    # TC001: 正常登录
    login("test", "123456")
    assert login_success()

def test_logout():
    # TC002: 登出（依赖TC001）
    logout()
    assert logout_success()

# 正确示例：测试用例独立
def test_login():
    # TC001: 正常登录
    login("test", "123456")
    assert login_success()

def test_logout():
    # TC002: 登出（独立）
    login("test", "123456")
    logout()
    assert logout_success()
```

#### 3. 可重复性
**说明**：测试用例应该可以重复执行

**实践方法**：
- 测试用例不依赖特定状态
- 使用测试数据准备脚本
- 每次执行前重置环境

**示例**：
```python
# 错误示例：测试用例不可重复
def test_login():
    # 第一次执行成功
    login("test", "123456")
    assert login_success()
    
    # 第二次执行失败（用户已登录）
    login("test", "123456")
    assert login_success()

# 正确示例：测试用例可重复
def test_login():
    # 每次执行前重置环境
    logout()
    login("test", "123456")
    assert login_success()
```

#### 4. 可维护性
**说明**：测试用例应该易于维护

**实践方法**：
- 使用清晰的命名规范
- 使用参数化设计
- 提取公共测试步骤
- 添加详细的注释

**示例**：
```python
# 错误示例：测试用例难以维护
def test_login():
    # 测试用例名称不清晰
    login("test", "123456")
    assert "success" in page_source()

def test_login_with_wrong_password():
    # 测试用例重复代码
    login("test", "wrong")
    assert "error" in page_source()

# 正确示例：测试用例易于维护
def test_login_with_valid_credentials():
    # 测试用例名称清晰
    login("test", "123456")
    assert "success" in page_source()

def test_login_with_invalid_credentials():
    # 使用参数化设计
    for password in ["wrong", "", "123"]:
        login("test", password)
        assert "error" in page_source()
```

### 测试用例设计技术

#### 1. 等价类划分
**说明**：将输入分为有效和无效等价类

**实践方法**：
- 识别输入的等价类
- 从每个等价类中选择代表性测试数据
- 覆盖有效和无效等价类

**示例**：
```python
# 用户名长度测试
# 等价类：
# - 有效：3-20字符
# - 无效：<3字符，>20字符

# 测试用例：
def test_username_valid():
    # 有效等价类
    for length in [3, 10, 20]:
        username = "a" * length
        assert validate_username(username) == True

def test_username_invalid():
    # 无效等价类
    for length in [1, 2, 21, 22]:
        username = "a" * length
        assert validate_username(username) == False
```

#### 2. 边界值分析
**说明**：测试输入输出的边界值

**实践方法**：
- 识别输入的边界
- 测试最小值、最大值、最小值-1、最大值+1
- 考虑数据类型的边界

**示例**：
```python
# 用户名长度边界测试
# 边界值：
# - 最小值：3
# - 最大值：20

# 测试用例：
def test_username_boundary_min():
    username = "a" * 3  # 最小值
    assert validate_username(username) == True

def test_username_boundary_min_minus_one():
    username = "a" * 2  # 最小值-1
    assert validate_username(username) == False

def test_username_boundary_max():
    username = "a" * 20  # 最大值
    assert validate_username(username) == True

def test_username_boundary_max_plus_one():
    username = "a" * 21  # 最大值+1
    assert validate_username(username) == False
```
