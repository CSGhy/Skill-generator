# 测试用例评审器

这个skill专注于测试用例的评审和质量检查，提供全面的测试用例评审服务，包括完整性检查、正确性检查、可执行性检查、可维护性检查等。

## 📋 快速参考卡片

### 基本指令格式

```
/test-case-reviewer [测试用例] [选项]
```

#### 参数说明

**必填参数**：
- `test-cases`：待评审的测试用例（必填）

**可选参数**：
- `--review-type`：评审类型，可选值：`completeness`|`correctness`|`executability`|`maintainability`|`all`（默认：`all`）
- `--standard`：评审标准，可选值：`standard`|`strict`|`custom`（默认：`standard`）
- `--output-format`：输出格式，可选值：`md`|`json`|`csv`（默认：`csv`）

#### 参数Schema

```json
{
  "test-cases": {
    "type": "string",
    "minLength": 1,
    "description": "待评审的测试用例"
  },
  "review-type": {
    "type": "string",
    "enum": ["completeness", "correctness", "executability", "maintainability", "all"],
    "default": "all",
    "description": "评审类型"
  },
  "standard": {
    "type": "string",
    "enum": ["standard", "strict", "custom"],
    "default": "standard",
    "description": "评审标准"
  },
  "output-format": {
    "type": "string",
    "enum": ["md", "json", "csv"],
    "default": "md",
    "description": "输出格式"
  }
}
```

### 常用命令

| 命令 | 说明 |
|------|------|
| "评审测试用例" | 评审测试用例质量 |
| "检查完整性" | 检查测试用例完整性 |
| "检查可执行性" | 检查测试用例可执行性 |
| "生成改进建议" | 生成改进建议 |

> 💡 **提示**：你可以直接粘贴测试用例，系统会按照评审标准进行全面的质量检查，并提供改进建议。例如："评审以下测试用例的质量"。

### 评审类型

| 评审类型 | 说明 | 检查项 |
|---------|------|--------|
| 完整性检查 | 检查测试用例是否覆盖所有需求 | 需求覆盖、场景覆盖、边界覆盖 |
| 正确性检查 | 检查测试用例是否正确 | 测试步骤、预期结果、数据正确性 |
| 可执行性检查 | 检查测试用例是否可执行 | 步骤清晰、前置条件、依赖关系 |
| 可维护性检查 | 检查测试用例是否易于维护 | 命名规范、结构清晰、复用性 |

## 常见问题

### 完整性问题

#### 问题1：需求覆盖不全

**现象**：某些功能需求没有对应的测试用例

**原因**：
- 需求分析不完整
- 测试设计遗漏
- 需求变更未更新测试用例

**改进建议**：
- 完善需求分析
- 建立需求-测试用例映射表
- 定期更新测试用例

#### 问题2：边界覆盖不足

**现象**：缺少边界值测试用例

**原因**：
- 边界分析不充分
- 测试设计经验不足

**改进建议**：
- 加强边界分析
- 使用边界值分析技术
- 参考边界值测试用例模板

### 正确性问题

#### 问题1：测试步骤不清晰

**现象**：测试步骤描述模糊，难以执行

**原因**：
- 测试设计不细致
- 测试人员经验不足

**改进建议**：
- 细化测试步骤
- 使用操作指导语言
- 参考测试步骤模板

#### 问题2：预期结果不明确

**现象**：预期结果描述模糊，难以验证

**原因**：
- 需求理解不充分
- 验证标准不明确

**改进建议**：
- 明确验证标准
- 使用可验证的描述
- 参考预期结果模板

### 可执行性问题

#### 问题1：前置条件不明确

**现象**：测试用例缺少前置条件说明

**原因**：
- 测试设计不完整
- 依赖关系分析不充分

**改进建议**：
- 明确前置条件
- 分析依赖关系
- 建立测试环境准备指南

#### 问题2：依赖关系复杂

**现象**：测试用例之间存在复杂的依赖关系

**原因**：
- 测试设计不合理
- 测试用例耦合度高

**改进建议**：
- 简化依赖关系
- 降低测试用例耦合度
- 使用测试数据准备脚本

### 可维护性问题

#### 问题1：命名不规范

**现象**：测试用例命名不符合规范

**原因**：
- 缺少命名规范
- 规范执行不严格

**改进建议**：
- 制定命名规范
- 严格执行规范
- 定期检查命名

#### 问题2：复用性差

**现象**：测试用例难以复用

**原因**：
- 测试用例设计不合理
- 缺少参数化设计

**改进建议**：
- 使用参数化设计
- 提取公共测试步骤
- 建立测试用例库

## 改进建议

### 完整性改进

#### 建议方法
1. **建立需求-测试用例映射表**
   - 确保每个需求都有对应的测试用例
   - 定期更新映射表

2. **使用测试设计技术**
   - 等价类划分
   - 边界值分析
   - 场景法

3. **定期评审测试用例**
   - 需求变更时更新测试用例
   - 定期检查测试用例覆盖

### 正确性改进

#### 建议方法
1. **细化测试步骤**
   - 使用操作指导语言
   - 明确每个操作的具体内容

2. **明确预期结果**
   - 使用可验证的描述
   - 明确验证标准

3. **验证测试数据**
   - 确保测试数据符合业务规则
   - 覆盖边界条件和异常数据

### 可执行性改进

#### 建议方法
1. **明确前置条件**
   - 列出所有前置条件
   - 确保前置条件可满足

2. **简化依赖关系**
   - 降低测试用例耦合度
   - 使用测试数据准备脚本

3. **提供测试环境准备指南**
   - 明确测试环境要求
   - 提供环境配置步骤

### 可维护性改进

#### 建议方法
1. **制定命名规范**
   - 制定测试用例命名规范
   - 严格执行规范

2. **提高复用性**
   - 使用参数化设计
   - 提取公共测试步骤
   - 建立测试用例库

3. **优化测试用例结构**
   - 合理分组测试用例
   - 保持测试用例层次分明
