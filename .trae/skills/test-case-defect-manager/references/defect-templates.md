# 缺陷模板库（test-case-defect-manager 参考）

本文件为 [../SKILL.md](../SKILL.md) 的缺陷录入参考，对齐公共标准
[缺陷 ID 格式](../_shared/standards.md#十-b缺陷-id-格式) 与工作区规则
`../../rules/缺陷报告规范.md`（P0-P4 分级、生命周期、附件要求）。

缺陷 ID 格式：`BUG_{模块缩写}_{序号}`（安全类可加 `SEC_` 前缀：`BUG_SEC_LOGIN_001`）。
模块缩写与 [standards 模块编号参考表](../_shared/standards.md#十模块编号参考表可扩展) 一致（USER/LOGIN/REG/PROD/CART/ORDER/PAY/REFUND/PERM/FILE…）。

---

## 一、标准缺陷录入模板（Markdown）

```markdown
# [模块名] 一句话描述问题

- 缺陷ID：BUG_LOGIN_003
- 标题：[登录页] 输入正确密码仍提示密码错误
- 模块：用户登录
- 测试环境：SIT
- 版本号：v1.2.3
- 浏览器/设备：Chrome 120
- 账号：testuser001
- 复现率：必现（10/10）
- 严重程度：P1
- 优先级：高
- 关联用例ID：LOGIN_001
- 指派给：zhangsan
- 报告人：lisi
- 创建时间：2026-08-20T14:30:00+08:00
- 状态：新建

## 复现步骤
1. 输入用户名 testuser
2. 输入正确密码 123456
3. 点击登录

## 预期结果
登录成功，跳转首页

## 实际结果
提示「密码错误」

## 附件
login_error.png, console.log

## 状态变更记录
| 时间 | 从 | 到 | 操作人 | 备注 |
|------|----|----|--------|------|
| 2026-08-20T14:30 | 新建 | 已指派 | lisi | 指派给后端 |
```

## 二、字段对照（必填 / 可选）

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| 缺陷ID | 是 | `BUG_{模块缩写}_{序号}` | BUG_LOGIN_003 |
| 标题 | 是 | `[模块名] 描述`，≤30字 | [登录页] 正确密码提示错误 |
| 模块 | 是 | 功能模块 | 用户登录 |
| 测试环境 | 是 | SIT/UAT/PROD | SIT |
| 版本号 | 是 | 版本/构建号 | v1.2.3 |
| 浏览器/设备 | 是 | 环境载体 | Chrome 120 |
| 账号 | 是 | 测试账号 | testuser001 |
| 复现步骤 | 是 | 1、2、3 编号 + 数据 | 见上 |
| 预期结果 | 是 | 应出现什么 | 登录成功 |
| 实际结果 | 是 | 实际发生什么 | 提示密码错误 |
| 严重程度 | 是 | P0-P4 | P1 |
| 优先级 | 是 | 紧急/高/中/低 | 高 |
| 复现率 | 是 | 必现/偶现/仅一次 | 必现 |
| 关联用例ID | 是 | 触发用例 | LOGIN_001 |
| 指派给 | 否 | 开发负责人 | zhangsan |
| 报告人 | 是 | 测试人员 | lisi |
| 创建时间 | 是 | ISO 8601 | 2026-08-20T14:30+08:00 |
| 状态 | 是 | 见生命周期 | 新建 |
| 附件 | P0/P1必附 | 截图/录屏/日志 | login_error.png |

## 三、严重程度分级（P0-P4）

| 等级 | 定义 | 示例 | 处置 |
|------|------|------|------|
| P0 | 致命，阻断发布 | 支付失败、数据丢失、全线登录不可用 | 立即修复，0 遗留阻断发布 |
| P1 | 严重，核心功能受损 | 登录偶现失败、主流程报错 | 本迭代内修复（≤72h） |
| P2 | 一般，次要功能异常 | 列表排序错误、非核心校验缺失 | 排期修复 |
| P3 | 轻微，体验/边缘 | UI 文案、提示语 | 可延后 |
| P4 | 建议，优化类 | 性能/体验优化建议 |  backlog |

---

## 四、生命周期状态机

```
新建 → 已指派 → 处理中 → 待验证 → 已关闭
                ↑                 ↓
                └── 重新打开 ←────┘
延期处理（确认有问题但本期不修）
不予处理（不是Bug / 重复 / 需求如此）
```

每次状态变更必须记录：时间、从、到、操作人、备注（见模板状态变更记录表）。

## 五、质量门禁模板（报告生成用）

| 门禁项 | 阈值 | 说明 |
|--------|------|------|
| P0 缺陷遗留 | = 0 | 任一 P0 未关闭即阻断发布 |
| P1 缺陷遗留 | ≤ 2 | 视规模可调 |
| 修复率 | ≥ 70% | 已关闭 / 总数 |
| 验证率 | ≥ 90% | 已关闭 / (已关闭 + 待验证) |
| P0/P1 平均修复时长 | ≤ 24h / 72h | 对齐优先级定义 |
