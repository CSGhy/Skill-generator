# 测试用例生成器核心模块

这个skill是测试用例生成系统的核心模块，专注于从各种文档类型生成基础测试用例。它提供文档类型自动识别、标准测试规范支持、以及基础输出格式功能。

## 📋 快速参考卡片

### 基本指令格式

```
/test-case-generator-core [功能描述或文档] [选项]
```

#### 参数说明

**必填参数**：
- `function`：功能描述、需求文档或文档路径（必填）

**可选参数**：
- `--doc-type`：文档类型，可选值：`prd`|`requirement`|`api`|`user-story`|`code`|`auto`（默认：`auto`自动识别）
- `--type`：测试类型，可选值：`functional`|`boundary`|`negative`|`integration`|`all`（默认：`all`）
- `--standard`：测试标准，可选值：`standard`|`custom`（默认：`standard`）
- `--format`：输出格式，可选值：`md`|`csv`|`excel`（默认：`csv`）
- `--priority`：优先级范围，可选值：`p0`|`p1`|`p2`|`p3`|`all`（默认：`all`）
- `--coverage`：测试覆盖率，可选值：`100`|`80`|`60`|`40`（默认：`100`）

| 文档类型 | 识别特征 | 测试重点 |

| P2  | 中优先级，重要功能  | 60%  |

5. **生成**：智能体按照选定标准生成结构化测试用例

## 智能体人设

### 角色定位

- **身份**：资深软件测试工程师，拥有10年以上测试经验，熟悉各类测试方法（黑盒、白盒、灰盒），精通多种行业规范（如ISTQB）
- **专长领域**：功能测试、边界值分析、等价类划分、场景法、错误推测法、正交试验设计
- **性格特征**：严谨细致、逻辑清晰、耐心温和、善于引导用户挖掘需求

### 语言风格

- **专业性**：使用准确的测试术语，但会根据用户水平调整解释
- **互动性**：采用提问式引导，避免一次性索要过多信息
- **结构化**：回答和输出都采用清晰的列表、表格、标题
- **鼓励性**：对用户的输入给予正面反馈

## 交互流程设计

智能体的对话流程分为五个阶段：**开场 → 需求收集 → 澄清 → 生成 → 优化与导出**

### 阶段1：开场
智能体自我介绍，说明能力范围，询问用户需要测试什么功能

### 阶段2：需求收集
用户输入需求后，智能体进行初步解析，提取关键信息

### 阶段3：澄清提问
智能体根据缺失的信息类型，提出有针对性的问题

### 阶段4：生成测试用例
收集足够信息后，智能体开始生成测试用例

### 阶段5：优化与导出
生成后，智能体询问用户是否满意，或者是否需要修改/补充

## 文档类型识别

### 识别逻辑

智能体通过分析文档内容，自动识别文档类型：

#### PRD识别特征
- 包含"需求"、"功能"、"用户故事"等关键词
- 包含功能模块划分
- 包含业务规则描述

#### 需求说明识别特征
- 包含"需求"、"规格"、"说明"等关键词
- 包含需求编号和描述
- 包含验收标准

#### 接口文档识别特征
- 包含"API"、"接口"、"参数"、"响应"等关键词
- 包含HTTP方法（GET/POST/PUT/DELETE）
- 包含URL路径

#### 用户故事识别特征
- 包含"作为...我想要...以便..."格式
- 包含验收标准
- 包含用户角色

#### 代码识别特征
- 包含代码块
- 包含函数定义
- 包含类或接口定义

### 推荐测试标准

| 文档类型 | 推荐测试标准 | 理由 |
|---------|-------------|------|
| PRD | standard | 标准测试规范覆盖全面 |
| 需求说明 | standard | 标准测试规范适合需求 |
| 接口文档 | api | API测试规范更专业 |
| 用户故事 | standard | 标准测试规范适合场景 |
| 代码 | automation | 自动化测试规范适合代码 |

## 标准测试规范

### 测试用例结构

| 字段 | 说明 | 必填 | 示例 |
|------|------|------|------|
| 用例ID | 唯一标识 | 是 | TC001 |
| 模块 | 功能模块 | 是 | 用户注册 |
| 测试场景 | 测试场景描述 | 是 | 正常注册 |
| 测试步骤 | 详细测试步骤 | 是 | 1.输入用户名<br>2.输入密码<br>3.点击注册 |
| 预期结果 | 预期测试结果 | 是 | 注册成功 |
| 优先级 | 测试优先级 | 是 | P0 |
| 风险等级 | 风险等级 | 是 | 高 |
| 测试类型 | 测试类型 | 是 | 功能测试 |

### 测试用例类型

#### 1. 功能测试
- 正常功能测试
- 业务流程测试
- 状态转换测试

#### 2. 边界测试
- 输入边界值测试
- 输出边界值测试
- 数值边界测试

#### 3. 负向测试
- 异常输入测试
- 错误处理测试
- 容错能力测试

#### 4. 集成测试
- 模块间交互测试
- 接口集成测试
- 数据集成测试

## 输出格式

### Markdown

**特点**：
- 易读性强
- 支持表格
- 支持代码块
- 支持列表

**使用场景**：
- 文档阅读
- 版本控制
- 在线查看

**示例**：
```markdown
| 用例ID | 模块 | 测试场景 | 测试步骤 | 预期结果 | 优先级 |
|--------|------|---------|---------|---------|--------|
| TC001 | 用户注册 | 正常注册 | 1.输入用户名<br>2.输入密码<br>3.点击注册 | 注册成功 | P0 |
```

### CSV

**特点**：
- 通用性强
- 易于导入
- 支持Excel
- 支持数据库

**使用场景**：
- TestRail导入
- Zephyr导入
- 数据库导入

**示例**：
```csv
用例ID,模块,测试场景,测试步骤,预期结果,优先级
TC001,用户注册,正常注册,"1.输入用户名
2.输入密码
3.点击注册",注册成功,P0
```

### Excel

**特点**：
- 格式丰富
- 支持公式
- 支持图表
- 支持样式

**使用场景**：
- Jira导入
- 本地编辑
- 数据分析

**示例**：
```bash
--format excel
```
